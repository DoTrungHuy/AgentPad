# AgentPad 产品设计：受治理的通用工具 Agent

- 日期：2026-07-16
- 状态：**已定稿（用户确认按推荐设计执行）**
- 核心诉求：会调工具、能推进任务；多类型 API Key；引导式对话；相册可选图（G0）与授权后本地检索（G1）
- 范围：v0.2.x → G0/G1 产品形态；不含 Accessibility Device Agent、不含 Runtime Shell

---

## 1. 一句话产品

**AgentPad 是 Android 上的本地 AI Agent 工作台：你接上自己的模型服务，用自然语言被引导着说清目标；它会选工具、调用工具、看结果、再决定下一步；只有可能产生外部影响或敏感动作时才来问你。**

它不是普通聊天框，也不是无边界全自动脚本。

---

## 2. 用户要的成品（验收语言）

用户完成一次任务时，应感到：

1. **会用工具**：读文件、总结、打开网页、启动应用、分享等，不是只会说话。
2. **会自动推进**：一步做完后，不必每次手点“基于结果继续”，它会根据观察继续。
3. **看得见过程**：正在调用哪个工具、结果是什么、下一步准备做什么。
4. **敢让它干**：敏感动作要审批；支付/密码/验证码/锁屏/静默安装永远不能做。
5. **能停能恢复**：可取消；异常退出后可从中断点重新审批继续。
6. **接得上自己的模型**：DeepSeek、OpenAI 兼容、国内常见中转/endpoint 都能配 API Key 用起来。
7. **会被引导**：目标含糊时，Agent 会追问澄清，而不是硬猜或直接失败。

### 成功样例（G0 必须能跑通）

> 「读这份报告，总结主要风险，如果有官网链接就打开。」

期望行为：

1. 自动调用 `read_document`（只读，可自动）
2. 把预览/内容纳入工作记忆
3. 自动调用 `upload_document_for_summary` 或本地摘要路径（需审批则先问）
4. 从结果中得到 URL 后，提出 `open_url`
5. 用户批一次网页操作后打开
6. 给出完成说明

全程用户主要做：选文件 + 必要时点允许。

## 3. 产品定位

| 是什么 | 不是什么 |
| --- | --- |
| 会调用工具的任务 Agent | 纯聊天助手 |
| 可换模型/API 的本地工作台 | 绑定单一厂商账号体系 |
| 会引导澄清目标的对话式 Agent | 只会执行完整指令的脚本 |
| 本地权威 + 人工审批 | 模型自由操作系统 |
| 多轮 observe → act 循环 | 一次性长计划死跑完 |
| Android 工作台 | 桌面无限权限 Agent |

**对外一句话：**  
「接上你的 API Key，像通用 Agent 一样被引导着完成任务；像安全产品一样每一步都受本地规则约束。」

## 3.1 模型与 API Key（一等产品能力）

> 此前版本设计偏重工具循环；**多服务商 / 多 API Key 与引导对话现提升为 G0 必做产品面。**

### 现状（不够）

- 仅 DeepSeek 预设 + 自定义 OpenAI-compatible
- 实质上 **只存一把 API Key**
- 无多配置档案、无按任务切换、无厂商向导

### 目标产品能力

#### A. 兼容面（协议）

| 接入方式 | 产品承诺 |
| --- | --- |
| OpenAI-compatible Chat Completions | **主兼容标准**（覆盖 DeepSeek、多数中转、自建网关、部分国产兼容层） |
| 预设厂商模板 | DeepSeek、OpenAI、通义/硅基流动/其他兼容方（模板可演进，核心是 endpoint+model+key） |
| 自定义 | 用户填 Base URL / 完整 chat completions URL、模型名、API Key |
| 本机回环 | 允许 `localhost` HTTP（本地 Ollama 等），其余默认 HTTPS |

**不做（G0）：**
- 强制 Google/OpenAI 官方 OAuth 登录
- 非 HTTP 的私有专有协议优先适配
- 云端代持用户 Key

#### B. 配置档案（用户怎么用）

用户可保存多个 **模型配置档案**，例如：

- 工作-DeepSeek
- 备用-兼容中转
- 本地-Ollama

每个档案包含：

- 显示名
- 服务商模板（deepseek / openai / custom / …）
- endpoint
- model
- API Key（Keystore 加密，相互隔离）
- 可选：温度/超时等（后置也可）

产品行为：

1. **首次启动引导**：选模板 → 填 Key → 一键测通 → 进入工作区  
2. **设置页**：切换当前默认档案；增删改；测连接  
3. **工作区顶栏**：显示当前档案/模型；可快速切换  
4. **连接失败**：可读错误（401/429/超时）+ 引导回设置，不甩堆栈  

#### C. 安全

- Key 永不进 Room 明文、日志、诊断、分享
- 每个档案独立密文
- 测试连接成功才允许设为默认（可覆盖，但要提示）
- 备份仍默认排除密钥

### 验收样例

1. 用户只带 DeepSeek Key → 3 步内测通可用  
2. 用户换自定义 OpenAI 兼容 endpoint + Key → 测通并切换成功  
3. 保存两套配置，顶栏切换后新任务走新模型  
4. Key 错误时提示“认证失败，请检查 API Key”，不泄露 Key

## 3.2 引导式对话（一等产品能力）

> Agent 不能只会“有完整指令才执行”。目标含糊时要会问；执行中缺信息要会要；完成后要会建议下一步。

### 三种对话态

| 状态 | 含义 | 用户看到 |
| --- | --- | --- |
| **澄清中** | 目标不清，先问再干 | 引导问题、选项/快捷回复 |
| **执行中** | 已够清楚，调工具推进 | 工具卡片 + 进度 |
| **等待你** | 要审批 / 要补充文件 / 要选择 | 审批卡、补附件、二选一 |

### 引导原则

1. **先问后猜**：缺文件、缺链接、缺应用名时，先问，不瞎调工具。  
2. **少问、问要点**：一次最多 1–3 个关键问题，给可点选项。  
3. **问完就干**：信息够了自动进入工具循环，不要用户再学术语。  
4. **执行中也可插话**：用户可追加约束（“别打开网页”“换个总结角度”）。  
5. **失败也引导**：工具失败时说明原因 + 给可选下一步（重试/换工具/改目标/取消）。  

### 典型引导脚本（产品文案级）

**冷启动：**
- “你想让我帮你处理什么？例如：总结文件、打开网页、整理要点并分享。”
- 快捷 chips：`总结文件` `打开网页` `启动应用` `自由描述`

**目标含糊（“帮我弄一下这个”）：**
- “我可以：① 读取并总结 ② 打开相关链接 ③ 分享摘要。你更想先做哪一步？”

**缺附件：**
- “需要你选一个文件。点下方「添加文件」后我会开始读取。”

**缺关键参数：**
- “要启动哪个应用？可输入包名，或从常见应用里选。”

**可开干：**
- “目标清楚了。我将：读取文件 → 总结风险 → 如有官网再请求打开。开始吗？”  
  （标准模式下只读可直接开始，打开网页仍审批）

### 引导与工具的关系

```text
用户一句话
  → 若信息不足：澄清（不调外部影响工具）
  → 若信息足够：进入工具循环
  → 循环中缺料：暂停并引导补充
  → 需要审批：引导允许/拒绝
  → 完成：总结 + 建议“继续做什么”
```

**重要：** 引导对话本身不是新权限；澄清阶段默认不调用 `open_url` / `launch_app` / `share` / 上传原文，除非用户已明确目标且策略允许。

### 验收样例

1. 用户只说“帮我看看” → Agent 追问对象与期望结果，不乱调工具  
2. 用户说“总结文件”但没附文件 → 明确引导添加文件  
3. 用户补全信息后 → 自动开始工具循环  
4. 任务完成 → 给出结论，并建议 1–2 个后续动作（可点）

## 4. 核心体验：工具是一等公民

### 4.1 当前可用工具（产品能力面）

| 工具 | 用户感知 | 默认审批 |
| --- | --- | --- |
| `inspect_task` | 检查任务状态 | 自动 |
| `read_document_metadata` | 看文件信息 | 自动 |
| `read_document` | 本机读文件 | 自动 |
| `upload_document_for_summary` | 把文件内容交给模型总结 | 逐步审批 |
| `open_url` | 打开 HTTPS 网页 | 任务审批 |
| `launch_app` | 启动已装应用 | 任务审批 |
| `share_preview` | 系统分享文本 | 任务审批 |

### 4.2 相册 / 图像访问（用户明确需要，分档交付）

> 场景：「帮我找 2024 年 5 月在海边的照片」「把这张发票图总结一下」。  
> **之前规格未写清；现纳入产品，但必须分清 Android 系统授权 vs AgentPad 任务审批。**

#### 先澄清一个常见误解

| 说法 | 对不对 |
| --- | --- |
| 「技术上无法授权全部相册」 | **不对**。Android 可以申请媒体库读权限，用户点允许后，应用能在授权范围内枚举/筛选照片。 |
| 「AgentPad 永远不能读全部相册」 | **也不对**。可以作为**用户明确开通的能力**。 |
| 「模型说一句话就该自动拥有全库权限」 | **对，这个不行**。权限只能来自系统授权 + 用户知情，不能来自模型。 |
| 「全库读了就可以静默全部上传云端」 | **不行**。本地索引/筛选 与 上传模型 必须拆开。 |

所以：  
- **禁止的是「无系统授权、无说明、静默全盘 + 偷传」**  
- **不是禁止「用户授权后，本地用全部（或所选）相册做查找」**

#### 本地实现是否可行？——可行

在用户授予媒体读权限后，**纯本地**可以做到：

1. 用 `MediaStore` 枚举图片 URI  
2. 按 **拍摄/修改日期、文件夹、体积、MIME** 过滤  
3. 生成缩略图列表给用户点选确认  
4. 不经过任何 API Key / 云端  

这是标准 Android 能力，不需要 Root，不需要无障碍。

限制在于系统与隐私政策，不在“写不出来”：

| 系统现实 | 含义 |
| --- | --- |
| Android 13+ `READ_MEDIA_IMAGES` | 可申请访问图片库 |
| Android 14+ 部分授权 | 用户可能只给「所选照片」，这时**没有**真正的“全部相册” |
| 用户点拒绝 / 仅本次 | 应用必须降级为 Photo Picker 或提示去设置开启 |
| 厂商相册差异 | 极少数图可能在特殊目录，MediaStore 未必全覆盖，但不能为此绕过沙箱 |

#### 能做什么 vs 不能做什么

| 能力 | G0 | G1 | 说明 |
| --- | --- | --- | --- |
| 用户点选 **一张/多张** 图片再给 Agent 分析 | **要做** | — | 系统 Photo Picker；无需全库权限 |
| **用户明确授权后**，本地访问全部（或系统允许范围内）相册元数据 | 可选 | **要做** | 系统权限弹窗 + 能力页开关 + 用途说明 |
| 按 **日期范围** 在已授权图库中 **本地筛选** | 简化版可做 | **要做** | 纯本地 MediaStore，可不上传 |
| 按 **内容/语义**（“海边”“发票”）查找 | 不做全库视觉扫描 | **有限做** | 本地仅元数据；语义需视觉模型且逐批审批上传 |
| Agent **未授权就遍历相册** | **禁止** | **禁止** | 安全红线 |
| **已授权本地检索**，但 **未再确认就批量上传全库** | **禁止** | **禁止** | 本地可读 ≠ 可云传 |
| 修改/删除用户照片 | **禁止（G0/G1）** | 以后单独立项 | 默认只读 |

**产品结论：**  
「授权全部相册后本地帮你找图」**可以实现，也建议支持**，条件是：

1. **系统权限弹窗**用户点了允许（或 Android 14 的「所选照片」——那只是子集，要如实显示）。  
2. **AgentPad 内有明确开关/说明**：例如「允许 Agent 在本机检索相册（只读，默认不上传）」。  
3. **检索默认本地完成**；只有用户确认「用模型看这些图」才上传候选集，而不是全库。  
4. **默认入门仍推荐 Photo Picker**（零持久全库权限）；需要“按日期帮我翻”时再引导开全库/媒体权限。

#### 授权怎么走（两层，不要混）

```text
第一层：Android 系统权限 / 系统选择器
  - Photo Picker：用户每次或批量点选图片（无持久全库权限，最安全）
  - 或 媒体权限弹窗：允许全部 / 允许所选 / 不允许

第二层：AgentPad 任务审批
  - 列出将访问的范围（例如：2024-05 的图片元数据，共 N 张）
  - 若要把图像内容发给云端模型：必须单独 ACTION 审批，并显示「将上传图像」
```

**会不会弹窗？会。**

| 弹窗 | 谁弹 | 何时 |
| --- | --- | --- |
| 系统权限对话框 | Android | 首次请求相册/媒体权限时 |
| 系统相册 / Photo Picker | Android | 让用户选图时 |
| AgentPad 审批卡 | App | 扩大范围、批量读、上传给模型时 |
| 部分照片访问（Android 14+） | 系统 | 用户可只授一部分图 |

**会被安全防线拦住吗？**

| 行为 | 结果 |
| --- | --- |
| 用户通过 Picker 选中的图，本机预览/读元数据 | 应允许（等同已授权附件） |
| 有媒体权限后，按日期筛元数据（不上传） | 标准模式可自动或任务级确认（产品可选） |
| 把图片字节发给云端视觉/多模态模型 | **必须审批**，默认不自动 |
| 无权限时模型要求「直接读全部相册」 | **本地拒绝**，引导去授权或打开选择器 |
| 读锁屏/其他 App 私有图、隐蔽上传 | **永久禁止** |

#### 推荐产品路径（避免一上来就全盘权限）

**路径 A（G0 必做，最简单）：**  
用户说「看看这张图」→ Agent 引导点「选择图片」→ 系统 Picker → 图作为附件 → 本机或经审批后多模态总结。

**路径 B（G1，本地全库/已授权库检索——可行且推荐作为「找照片」主路径）：**  
用户说「找 5 月的照片」→ Agent 说明需要相册只读权限 → **系统权限弹窗** → 用户允许全部或所选 → **本地 MediaStore 按日期筛** → 缩略图候选列表 → 用户确认 → 若还要内容识别，再审批后把**候选**（不是全库）发给模型。

**路径 C（不做）：**  
模型一句「我自己去相册翻」→ 无 UI、无系统授权、全盘静默读传。

#### 「授权全部相册」的产品形态（若用户坚持要）

可以做成设置/能力里的明确项：

- 开关名：`允许本机检索相册（只读）`  
- 打开时：触发系统权限请求  
- 开启后 Agent 可：按日期/文件夹列图、展示缩略图、供用户挑选  
- 开启后 Agent 仍不可：静默上传全库、删改照片、在拒绝权限后继续硬扫  

这与安全哲学不冲突：**权限来自用户 + 系统，用途本地检索，上传另审。**

#### 用户可见文案原则

- 权限用途一句话说清：「用于按你的条件查找和展示照片，不会在未确认时上传。」  
- 上传前再挡一层：「将把 N 张图片发送到你配置的模型服务，是否允许？」  
- 能力页写清：当前是「选图分析」还是「已授权图库检索」。

### 4.3 明确暂不可用（能力页显示「计划中」）

- 跨应用点击/输入/滑动（Device Agent）
- 写/删任意文件、发短信、截屏上传默认开启
- 无提示的全盘相册扫描与静默上传
- Shell / Python / Git Runtime
- 支付、密码、验证码、锁屏、静默安装（永久禁止）

### 4.4 工具使用规则（产品规则，不只是技术）

1. 模型只能提议已启用工具。
2. 每个工具调用都有结果卡片：成功/失败/证据摘要。
3. 失败后 Agent 应解释并尝试替代路径，或请求用户决策；不能假装成功。
4. 同一任务内，已批准的同类中风险动作可按模式复用授权（见运行模式）。
5. 涉及相册/图像：系统授权与 AgentPad 审批分层；上传云端默认逐步确认。

## 5. 运行模式（用户可懂）

| 模式 | 行为 | 默认 |
| --- | --- | --- |
| **谨慎** | 除纯只读外，几乎都要确认 | 否 |
| **标准** | 只读自动；打开网页/启动应用/分享等本任务批一次 | **是** |
| **高效** | 本任务内已批准的中风险工具可继续用，直到任务结束或取消 | 否 |

三种模式都**没有**“跳过禁止类”的选项。

## 6. Agent 如何工作（用户可见流程）

```text
你提出目标
  → Agent 规划下一步（可能直接选工具）
  → 本地判断：自动 / 要审批 / 禁止
  → 调用工具
  → 展示结果观察
  → 自动决定下一步
  → …直到完成、失败、需你决策、或达到上限
```

### 时间线应出现的卡片类型

- 用户目标
- 思考/计划摘要（可折叠）
- 工具调用（名称、参数摘要、结果）
- 审批请求（允许本次 / 本任务同类 / 拒绝）
- 状态（执行中、已中断、已取消）
- 最终结论

### 停止条件（产品保证）

满足任一即停：

- 目标完成
- 用户取消
- 工具失败且无法安全继续
- 达到步数/模型调用/时间上限
- 需要审批而用户拒绝
- 触达禁止操作

## 7. 分阶段产品交付

### G0：会调工具 + 接得上模型 + 会引导（当前主交付）

**目标：** 从“一次计划跑完”升级为“可配置模型 + 引导澄清 + 调用工具 → 看结果 → 再调用工具”。

必须有：

1. 自动多轮工具循环（受预算限制）
2. 每步工具结果写回上下文
3. 标准/谨慎/高效模式
4. 步骤流可见
5. 暂停/取消
6. 现有工具全部可被循环调度（不只是预生成计划里的死序列）
7. **多模型配置档案 + 多 API Key（加密隔离）+ 连接测试引导**
8. **引导式对话：澄清 / 补文件 / 失败恢复 / 完成后建议**
9. **首次使用向导：选服务商模板 → 填 Key → 测通 → 示例任务**
10. **图像最小闭环：系统选图（Photo Picker）→ 作为附件 → 可选本机信息展示；上传模型分析需审批**

**不做：** 无障碍、Runtime、新高危工具、OAuth 强制登录、无提示全盘相册扫描。

### G1：工具变强 + 模型体验增强（通用任务包）

在 G0 稳定后：

- 多文件附件
- 更好的文档分块摘要
- 常用应用名→包名辅助
- App 私有目录笔记写入（需审批）
- 更清晰的工具失败恢复建议
- 更多厂商一键模板与模型列表提示
- 按线程记住偏好模型（可选）
- **相册：权限说明 + 按日期筛选已授权图片 + 候选列表确认**
- **图像：经审批后的多模态/视觉模型分析（依赖用户配置的 vision endpoint）**

### G2：Device Agent（跨应用）

另阶段；需独立安全门禁与紧急停止。不塞进 G0。

## 8. 界面产品要求（服务“会调工具”）

沿用 ZCode 工作台方向，但信息架构以 Agent 事件流为主：

1. **中栏时间线**：工具调用是主角，不是附属日志  
2. **底栏 Composer**：固定输入目标/追问  
3. **右栏/检查器**：当前待审批动作、已授权范围、预算剩余  
4. **状态条**：规划中 / 调工具中 / 待审批 / 已完成  

手机上审批以卡片或底部 sheet 出现，避免打断到找不到。

---

## 9. 安全与信任（产品承诺）

用户应始终相信：

1. 模型不能自己加薪权限  
2. 没批准的外部动作不会发生  
3. 禁止类永远不做  
4. 历史与密钥在本机；诊断导出需主动操作  
5. 能随时取消  

---

## 10. 成功指标（产品）

| 指标 | G0 目标 |
| --- | --- |
| 工具任务完成率（读文件+总结类） | 主路径可独立完成 |
| 用户平均干预次数 | 标准模式下 ≤ 2 次/任务（通常 0–1 次审批） |
| 误执行外部动作 | 0（无审批不得 open/launch/share） |
| 用户是否理解“它在用工具” | 时间线可见工具名与结果 |
| 取消有效 | 取消后不再继续调工具 |
| 新用户接通模型 | 首次 5 分钟内完成 Key 配置并测通 |
| 多配置切换 | ≥2 个档案可保存并切换成功 |
| 含糊目标不瞎执行 | 无关键信息时先澄清，不调用外部影响工具 |
| 引导后转化 | 澄清完成后能自动进入工具执行 |

## 12. 对现有版本的关系

已具备：

- 工具注册表、审批、执行引擎、线程工作区、基础工具

G0 要补的关键产品缺口：

- **自动工具循环**（observe → next tool）
- **工具过程可见**
- **模式化授权**
- 减少手点“基于结果继续”

不是推倒重做，而是把“会规划”升级成“会持续用工具干活”。
